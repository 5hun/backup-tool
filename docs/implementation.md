# 初期実装の判断と検証

要件書: [windows_backup_tool_requirements_design.md](../windows_backup_tool_requirements_design.md)

## 設計上の選択

| 論点 | 初期実装 |
| --- | --- |
| 方式の混在 | 標準ZIP。UncompressedFoldersでタスク内の複数フォルダを非圧縮指定。深い例外ではZIPユニットを分割し重複を防ぐ |
| 階層未満のファイル | 各フォルダの `_files.zip`。空フォルダにも空ZIPを配置。出力衝突は実行前に拒否 |
| 非圧縮のユニット粒度 | ZIPと共通の UnitDepth。浅いフォルダでは直下ファイルだけを処理 |
| 削除差分 | ローカル一時SQLite。元と先を逐次列挙し、削除直前にも元の祖先を列挙して不在を確認 |
| ZIPの検証 | 毎回 `7za t` によるCRC全体検証。元のパス・サイズ・更新日時も構築前後に比較 |
| ZIP更新 | 7-Zipのupdate action setで未変更エントリ再利用。元の日時が旧ZIPより古い変更も反映 |
| 一時ZIP | 正式ZIPと同一フォルダ。一時ZIP完成後にFile.Replace。未作成先はFile.Move |
| 権限 | Robocopy /ZB。終了コード16なら /Z で一度再試行。OSの保護・権限を回避する実装はしない |
| ログ | ローカルSQLiteの実行/ユニット集計とテキスト詳細。通常成功ファイルの詳細は抑制。90日既定 |
| スケジュール | N日ごと、N週ごとの複数曜日、毎月の複数日付・月末・実行月、複数時刻。現在のユーザーのInteractiveToken、またはPasswordログオン |
| 排他 | DBごとの実行ロックと保存先のファイルロック。単一DB内のタスク実行を直列化 |
| 既存データ保護 | 空の専用保存先を必須とし、所有マーカーでタスクと元の対応を固定 |

## 現在の実装範囲

フェーズ1〜3の基本機能として、タスク保存、ユニット分割、ランダム順・前回未完了優先、ZIP/Robocopyのタスク内混在、差分・削除、ローカル実行履歴、WPF画面、手動実行・中断、日次・週次・月次スケジュールの登録を実装しています。エンジンはGUIとCLIで共通です。

非圧縮の例外は配下にも適用し、重複指定は親フォルダへ集約します。相対パス以外・元の範囲外は拒否します。出力のZIPと非圧縮パスの衝突は実行前に検出します。例外を変更すると、旧出力は全ユニット成功後に新しい出力を保護しながら整理します。既存の全体非圧縮タスクは互換性のため維持します。GUIでは新規タスクの方式選択を廃止しています。

一部のファイルが読み取れないZIPはユニット全体を失敗とし、旧ZIPを保持します。他のユニットは継続します。いずれかのユニットにエラーがあると、その回の削除フェーズは全体をスキップします。

## 残る制限・受入試験

- フェーズ4の数十万〜数百万件、実NASでの性能・故障試験は未実施です。SMBサーバーごとのFile.Replace対応・障害時の動作を確認する必要があります。置換が非対応ならエラーにし、旧ZIPを意図的に削除する代替処理は行いません。
- OS停止直前までの書込みの永続化、複数PC・異なるDBで包含する保存先を利用する運用、バックアップ中に変わるファイルの一貫性は保証しません。同一保存先を複数PCで管理しないでください。
- 非圧縮では元・保存先の列挙に通常権限が必要です。Robocopyがバックアップ特権でコピー可能でも、事前列挙が拒否されるユニットはエラーにします。ZIPのファイル読取りも通常の実行アカウントの権限を使います。
- タスク開始時の共有アクセスは指数バックオフで再試行します。処理中の切断ではRobocopyのファイル再試行とユニット失敗記録を使用します。共有全体の切断を検出して処理中の全ユニットをまとめて一時停止する制御は、実NASでの検証とあわせて追加する余地があります。
- VSS、ACL保持、暗号化ファイルの権限突破、復元用GUI、大量削除の閾値は未実装です。
- 実行中の進捗表示・中断は、そのGUIから開始した実行が対象です。別CLI/スケジュールで開始した実行は履歴の再読込で確認します。
- 次回予定は保存したスケジュールから計算します。Windows側で設定を直接変更した場合は反映しません。存在しない月日はスキップし、月末指定ならその月の最終日を使います。スケジュールの実機登録・ログオフ中のNAS接続は利用アカウントで確認が必要です。
- ファイルはサイズ・更新日時で比較します。同一サイズ・同一更新日時の内容変更は検出しません。
- 単一ディレクトリ内を含め列挙は逐次処理します。ただしユニット一覧・ユニット状態はメモリに保持します。ユニットが極端に多い場合は追加の最適化が必要です。

## ローカル検証結果

- 全5プロジェクトのビルド成功（警告0、エラー0）。
- 実7-Zip/Robocopyによる統合テスト28件成功。既存の20件に加え、深い例外の混在・差分・削除、例外変更時の旧出力整理と失敗時の保持、パス衝突、日次・複数曜日・月末・閏年の次回予定、旧DailyAtの移行を確認。
- Windowsのタスク定義オブジェクトで日次・週次・月次のトリガーとXMLを確認（OSへのタスク登録は行わない）。
- 配布版GUIをWindows UI Automationで起動し、週次の複数曜日・複数時刻、月次の日付・月末と非圧縮指定の保存、手動のZIP/非圧縮混在バックアップを確認。実行履歴のフィルタ幅は通常サイズ・最小ウィンドウサイズの両方で確認。`scripts/smoke-gui.ps1` で再実行できます。
- `scripts/publish.ps1` によるCLI/GUI/7-Zip同梱の配布フォルダ作成を確認。
